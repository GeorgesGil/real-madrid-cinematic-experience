# Domain documentation

This repository uses a single-context domain layout.

Before exploring, read `CONTEXT.md` when it exists and any relevant decisions under `docs/adr/`. Missing domain files are not a blocker; create or extend them only when the work resolves meaningful terminology or architectural decisions.

Use the vocabulary defined in `CONTEXT.md` consistently in code, tests, specifications, and issue titles. Surface conflicts with existing ADRs explicitly instead of silently overriding them.
